# Portfolio security checklist

Checked 10 October 2026. The portfolio publishes static pages and public basketball data. It has no visitor accounts, database, uploads, or paid API calls. The local branch now has dependency patches, browser security policies for both hosts, and the corrected canonical address. Production release, live header verification, and hosting account checks remain pending.

I reviewed the application source, configuration, existing production output, and 69 commits reachable from local Git refs. I scanned 2,506 Git blobs for common provider keys, private keys, and credential assignments without printing potential values. I checked the home page, both NBA pages, the data manifest, HTTPS redirects, and sensitive development paths on both live hosts. This review does not certify the site against every attack or cover hosting dashboards, remote-only Git history, deleted unreachable objects, or arbitrary secret formats.

## Repair progress

1. Dependency patches are complete locally. The initial npm audit reported nine affected packages: one critical, seven high, and one moderate. The patch operation stayed within the existing version ranges, changed no direct dependency list, and cleared the audit to zero. Astro is now 7.3.8 and Sharp 0.35.5. The production build passes. The [Astro advisory](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2) requires processing an untrusted AVIF image; this static site has no visitor upload or server image endpoint in its source.
2. Browser security policies are complete locally. Astro generates script/style hashes in each page's CSP meta element, with resources restricted to the current origin. Script attributes remain blocked. Style attributes remain permitted for existing swatches and highlighting. The matching host CSP headers block framing, plugins and form submissions without a second script rule that would conflict with the generated hashes. The other headers deny framing, prevent MIME guessing, limit referrer information, and disable unused device/payment capabilities. See [Astro's CSP configuration](https://docs.astro.build/en/reference/configuration-reference/#securitycsp), [Vercel's header guidance](https://vercel.com/docs/cdn-security/security-headers), and [Netlify's header guidance](https://docs.netlify.com/manage/routing/headers/).
3. The canonical-address correction is complete locally. All seven HTML pages, sitemap files and RSS use `https://www.nslanalytics.com`. The serving-address documentation distinguishes this local repair from the public deployment.
4. Account checks await sign-in. GitHub, Vercel and Netlify displayed login screens in Chrome. The GitHub API returned only `nanu731` as a repository collaborator. GitHub MFA was not exposed by the API. No account settings, collaborators, environment variables, billing configuration or credentials were changed. [Astro documents which environment variables reach browser code](https://docs.astro.build/en/guides/environment-variables/).

## Local verification

The production build passes. Its existing empty-blog warnings remain. Astro also emits warnings about attribute-specific CSP rules and Shiki inline styles; the scoped style-attribute exception preserves those styles without allowing inline JavaScript. Hash checks confirmed that all built HTML pages contain CSP and that each inline script matches a generated hash. The two host header maps match.

Both explorers load in an isolated release build served with the exact matching host response headers. Both passed all eighteen slider/view combinations in 2025-26 and loaded LeBron across all five seasons. Checks covered player search, LeBron and Wembanyama, comparison reset, keyboard selection, range keys, radio keys, contextual help opening and Escape dismissal, and Chris Paul's unavailable estimates. The 2024-25 map remains usable without showing estimates; the 2025-26 ineligible state gives the existing reason and retains the previously recorded Loading placeholder. No application source or public data changed.

Chrome confirmed actual viewports of 1440 × 1000 and 375 × 812. Both pages had no horizontal overflow or application console warnings or errors. Chrome blocked the framed child page served with the configured framing headers. The negative inline-script/event-handler fixture was blocked by the browser client before navigation, so that attempt does not prove CSP enforcement. Static checks verified hash permissions and `script-src-attr 'none'`; normal scripts ran under both policies.

The release worktree starts at remote main `adbae3f` and contains only the five reviewed security commits. The dependency list, application source and public data match remote main. Clean installation, a fresh zero-vulnerability audit, production build, seven page-policy checks, four inline-script hash checks, metadata checks, and scans of 2,503 published files passed. Prototype assets, layout-test content, design tooling, environment files and source maps are absent from the release output. The original untracked files remain outside the release.
